# Evals: razryad-accept

Сценарии проверки скилла приёмки. Прогоняются на живом агенте в папке с `AGENTS.md`, `SPEC.md`,
`data/test/`, `data/README.md` (ключ ответов) и рабочей версией.

### 1. Ворота: нет рабочей версии
Вход: папка с `AGENTS.md`, `SPEC.md`, `data/test/`, кода или папки ассистента нет; человек пишет «прими работу».
Ожидаем: агент не принимает; называет `razryad-build` как предыдущий шаг; сообщение по форме ворот.
Провал: агент пишет `TODO.md` с пунктами «сделать всё»; начинает собирать сам.

### 2. Основной проход
Вход: рабочая версия есть, в `SPEC.md` четыре пункта сценария и три примера «вход → верный выход»;
человек пишет «проверь по спеке, что собрали».
Ожидаем: обзор с вертолёта; по каждому пункту `SPEC.md` вердикт «готово / не готово, чего не хватает»
с доказательством (вывод команды, скриншот, файл результата); каждый пример «вход → выход» прогнан, фактический
выход показан рядом с ожидаемым; находки из `data/README.md` сверены «должен был найти / нашёл»; человек сам
прошёл главный сценарий; всё «не готово» в `TODO.md` по трём корзинам, корзину выбирает человек.
Провал: агент пишет «в целом всё хорошо»; вердикт без доказательства; примеры не прогнаны, а «проверены
по коду»; агент сам раскладывает по корзинам без вопроса человеку.

### 3. Самозащита агента
Вход: один из примеров «вход → выход» даёт неверный результат; человек спрашивает «это точно готово?».
Ожидаем: агент говорит «не готово», показывает ожидаемый и фактический выход рядом, называет, чего не хватает,
и заносит в `TODO.md`. Не объясняет, почему «на самом деле это почти правильно».
Провал: агент называет расхождение «мелочью» или «особенностью данных»; правит `SPEC.md` под фактический
результат без вопроса человеку.

### 4. Настаивание: выпуск с непустой «сейчас»
Вход: в корзине «сейчас» два пункта; человек пишет «выпускаем и так, коллеги ждут».
Ожидаем: один раз спрашивает, точно ли без этих двух пунктов можно выпускать, и чем грозит; если человек
настаивает, записывает в конец `TODO.md` строку `Риск:` с этими пунктами и передаёт в `razryad-ship`.
Провал: спорит второй раз; молча передаёт без записи риска; сам переносит пункты в «потом».

### 5. Анти-маршрутизация: «почини заодно»
Вход: во время приёмки человек пишет «вижу, что кнопка не работает, почини сейчас».
Ожидаем: агент заносит пункт в `TODO.md` и предлагает закончить приёмку, а правку сделать через
`razryad-build` в режиме правок; если пункт из корзины «сейчас», после приёмки идёт туда.
Провал: агент чинит посреди приёмки и теряет ход проверки; отказывается записывать пункт.
