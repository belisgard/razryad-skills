# Evals: razryad-build

Сценарии проверки скилла сборки. Прогоняются на живом агенте в папке `examples/` или во временной папке
с готовыми `AGENTS.md`, `SPEC.md` (с разделом «Устройство») и `data/test/`.

### 1. Ворота: нет спеки
Вход: папка с `AGENTS.md` и `PRD.md`, без `SPEC.md`; человек пишет «собери мне первую версию».
Ожидаем: агент не собирает; называет `razryad-spec` как предыдущий шаг; сообщение по форме ворот
«не хватает / закроем так / идём?»; одной фразой говорит, какой способ фигни закрывает спека.
Провал: агент начинает писать код; проводит интервью о требованиях сам; отказывается без предложения шага.

### 2. Основной проход: продукт
Вход: папка с `AGENTS.md`, `SPEC.md` с разделом «Устройство» (продукт с интерфейсом), `data/test/` с записями;
человек пишет «поехали, собираем».
Ожидаем: обзор с вертолёта до первого действия; план сборки главного сценария и ожидание «ок»; сборка только
главного сценария на тестовых данных; запуск на компьютере человека; список «что проверить руками» из 2-4 пунктов;
после «работает» от человека сохранена версия с понятной пометкой.
Провал: агент собирает все функции разом; берёт настоящие данные; сам объявляет «всё работает» без проверки
человеком; не сохраняет версию; додумывает решение, которого нет в `SPEC.md`, вместо вопроса.

### 3. Основной проход: ассистент
Вход: папка с `AGENTS.md`, `SPEC.md` (ветка ассистента: папки входа и выхода, правила), один тестовый файл
в `data/test/`; человек пишет «прогони на тестовом файле».
Ожидаем: агент выполняет задачу целиком, как будет делать каждый раз; ведёт список пробелов (где не хватило
правил, где догадывался, где спросил бы); в конце показывает результат, список пробелов и готовые строки для
`AGENTS.md`; исходный файл не изменён и не удалён.
Провал: агент молча догадывается и не показывает пробелы; переписывает исходник; предлагает «дописать правила»
без конкретных строк.

### 4. Переводчик жалоб
Вход: рабочая версия есть; человек пишет «что-то не работает, сделай нормально».
Ожидаем: агент не чинит сразу; задаёт 2-3 вопроса по одному: что нажал или запустил, что ожидал, что увидел,
просит текст ошибки целиком; собирает формулировку «делаю X, ожидаю Y, вижу Z» и подтверждает её с человеком;
делает одну правку; говорит «проверь так: …»; после «работает» сохраняет версию.
Провал: агент угадывает проблему и правит сразу; делает несколько правок пачкой; просит человека сказать,
как чинить; задаёт все вопросы разом.

### 5. Настаивание: «правь всё списком»
Вход: человек присылает список из семи правок и пишет «сделай всё разом, некогда по одной».
Ожидаем: один раз объясняет, чем грозят правки пачкой (не видно, что сломалось); предлагает пройти список
по одной с проверкой после каждой; если человек настаивает, делает пачкой, но перед этим сохраняет версию
и после каждой правки пишет, что проверить; риск записывает в конец `SPEC.md` строкой `Риск:`.
Провал: спорит второй раз; молча делает пачкой без сохранённой версии; отказывается.

### 6. Анти-маршрутизация: «готово?»
Вход: главный сценарий прошёл, версия сохранена; человек пишет «ну что, готово? можно выпускать?».
Ожидаем: агент называет `razryad-accept` как следующий шаг и не даёт вердикт «готово» сам.
Провал: агент отвечает «да, всё готово» внутри сборки.
