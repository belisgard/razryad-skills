# Контракт набора razryad-skills

Документ для авторов скиллов набора. Пользователю его читать не нужно. Каждый скилл соблюдает этот контракт,
и линтер `scripts/validate.py` проверяет то, что можно проверить механически.

## Кому и зачем набор

Человек только начинает работать с ИИ-агентом (Claude Code или Codex) и хочет собрать первый инструмент или
продукт под свою рабочую задачу. Он не программист. Набор ведёт его по пути от выбора задачи до измеренного
эффекта так, чтобы в конце не получилась фигня: ненужный, непроверенный, небезопасный или брошенный инструмент.

Роли: человек решает, агент делает. 0% кода руками, 100% решений за человеком.

## Единица набора

Скилл = один вопрос, на который человек отвечает, + один файл в проекте + ворота.

| Скилл | Вопрос | Файл | Предыдущий файл (нужен для старта) |
|---|---|---|---|
| `razryad` | Где я и что дальше? | `AGENTS.md`, `CLAUDE.md` | нет |
| `razryad-task` | Что делать первым и как это идёт сейчас? | `PROCESS.md` | `AGENTS.md` |
| `razryad-prd` | Что строим, для кого, зачем? | `PRD.md` | `PROCESS.md` |
| `razryad-spec` | Как работает и что значит «правильно»? | `SPEC.md` | `PRD.md` |
| `razryad-proto` | Это то, что нужно? Как устроено? | макет или каркас, раздел «Устройство» в `SPEC.md` | `SPEC.md` |
| `razryad-data` | На чём проверять безопасно? | `data/test/`, `data/README.md` | `SPEC.md` |
| `razryad-build` | Как заставить работать и как говорить с агентом? | рабочая версия, сохранённые версии | `SPEC.md`, `data/test/` |
| `razryad-accept` | Готово ли? | `TODO.md` | `SPEC.md`, рабочая версия |
| `razryad-ship` | Как сделать, чтобы работало без меня и у других? | `README.md`, ссылка или расписание | `TODO.md` |
| `razryad-effect` | Сколько сэкономили честно? | `EFFECT.md` | `PROCESS.md`, `README.md` |
| `razryad-demo` | Как показать за 3 минуты? | `DEMO.md` | `EFFECT.md` |
| `razryad-retro` | Что я понял? | `JOURNAL.md`, правки `AGENTS.md` | любой |

Стадия проекта нигде не хранится. Она выводится из наличия файлов: есть `PRD.md`, нет `SPEC.md`, значит
человек в фазе «Проект» и следующий шаг `razryad-spec`.

## Структура папки скилла

```
skills/razryad-<x>/
  SKILL.md          до 150 строк, роутер: шаги в одну строку, детали по ссылке
  assets/           шаблоны файлов, которые скилл создаёт в проекте (`<NAME>.template.md`)
  references/       подробности, до 120 строк каждый файл
```

Папка самодостаточна: `SKILL.md` ссылается только на файлы внутри своей папки. Другие скиллы упоминаются
по имени (`razryad-spec`), без путей. Общие правила поведения повторяются в каждом SKILL.md короткой копией
в секции «Как ведём себя» (5-7 строк). Полная версия правил живёт в конституции проекта
(`skills/razryad/assets/AGENTS.template.md`), которую все скиллы читают нулевым шагом.

## Фронтматтер

```yaml
---
name: razryad-<x>
description: "Use when <условие по-английски, одна фраза>. <Одна фраза сути по-русски: на какой вопрос отвечает>.
  Триггеры: «фраза 1», «фраза 2», «фраза 3», «фраза 4». Не используй для <…>; для <смежного> см. razryad-<y>."
metadata:
  version: 0.1.0
  authors: Игорь Кузнецов
---
```

Правила description:

- начинается с `Use when`, это условие срабатывания, а не пересказ шагов скилла;
- содержит не меньше четырёх реальных фраз человека в кавычках-ёлочках: как он это скажет, а не как назвал бы
  методолог («что-то не работает», а не «инициировать цикл отладки»);
- содержит анти-маршрутизацию: `Не используй для …; для … см. razryad-<y>`;
- весь блок фронтматтера до 1024 символов.

## Тело SKILL.md

Порядок секций обязателен, линтер проверяет заголовки.

1. `# razryad-<x>: <вопрос, на который отвечает>` и 2-3 строки сути.
2. `## Что это / что не это`: три строки «это», три строки «не это».
3. `## Как ведём себя`: короткая копия правил из конституции, 5-7 строк, только те, что важны для этого шага.
4. `## Шаг 0. Контекст`: прочитай `AGENTS.md` (или `CLAUDE.md`), прочитай файлы предыдущих шагов. Если их нет,
   назови предыдущий скилл и не начинай. Затем обзор с вертолёта: 5-8 строк до первого вопроса, что человек
   получит, сколько шагов, сколько это займёт времени, где решает он, а где делает агент.
5. `## Шаги`: нумерованные, каждый шаг в 1-3 строки, детали стрелкой `→ references/<file>.md`. Интервью по одному
   вопросу. Каждый шаг заканчивается «ок» человека.
6. `## Формат результата`: какой файл создаётся, по какому шаблону из `assets/`, что в нём обязательно.
7. `## Ворота`: условие выхода как проверяемое утверждение; как о нём говорить; что делать, если человек
   настаивает идти дальше.
8. `## Дальше`: следующий скилл и когда другой.

Платформенная пометка там, где нужна, одной строкой: «режим плана: в Claude Code Shift+Tab до Plan, в Codex `/plan`».

## Ворота

Ворота это не запрет, а недостающий кусок. Форма сообщения:

> До следующего шага не хватает: <что>. Закроем так: <как, 1-2 действия>. Идём?

Если человек настаивает идти дальше без закрытия: записать в конец файла шага строку
`Риск: <что не закрыто и чем грозит>` и идти. Спорить один раз, не больше.

Ворота формулируются как проверяемое утверждение о файле или поведении, не как ощущение:

- хорошо: «в `SPEC.md` есть не меньше трёх примеров “вход → верный выход” с конкретными значениями»;
- плохо: «спека достаточно подробная».

## Как скиллы говорят с человеком

- На «ты». Уверенно, без хайпа, без снисхождения. Человек субъект: «ты решаешь», не «мы тебя научим».
- По одному вопросу за раз. Общие слова не принимаются, просить цифры и примеры.
- Перед первым вопросом обзор с вертолёта. Не вываливать список скиллов набора: назвать один следующий шаг.
- Без техно-жаргона, где есть русский аналог: «выложить на сервер», не «деплой»; «модель», не «LLM»;
  «сохранить версию», не «коммит» (git при этом используется, слово «git» допустимо как название инструмента).
- Цифры эффекта это оценка, не факт: рядом с цифрой всегда «как посчитано» и план замера.
- Агент не защищает свою работу. «Готово / не готово, чего не хватает».
- Агент не додумывает: если решения нет в файлах проекта, спрашивает.

## Ограничения текстов

- Без длинных и средних тире (em dash и en dash). Запятая, двоеточие, точка, скобки или дефис с пробелами.
- Без названий компаний-клиентов, ФИО реальных участников, адресов серверов, токенов, паролей.
- Примеры задач обезличены: роль и процесс, без бренда компании.
- Обращение к человеку на «ты», к агенту в императиве.
- Файлы проекта называются латиницей заглавными: `PROCESS.md`, `PRD.md`, `SPEC.md`, `TODO.md`, `README.md`,
  `EFFECT.md`, `DEMO.md`, `JOURNAL.md`, `AGENTS.md`, `CLAUDE.md`.

## Evals

На каждый скилл файл `tests/razryad-<x>-evals.md`, 3-5 сценариев. Формат сценария:

```
### <номер>. <название>
Вход: <состояние папки + что говорит человек>
Ожидаем: <наблюдаемое поведение агента, 2-5 строк>
Провал: <что считается провалом>
```

Обязательные сценарии: срабатывание ворот (предыдущего файла нет), анти-маршрутизация (запрос про смежный
скилл), основной проход, попытка человека идти дальше без закрытия ворот.

Evals пишутся до текста скилла или вместе с ним. Скилл считается готовым, когда сценарии прогнаны
на живом агенте (догфуд на `examples/`) и поведение совпало.

## Версии

`metadata.version` у всех скиллов одинаковый и равен версии набора в `CHANGELOG.md`.
