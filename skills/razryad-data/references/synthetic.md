# Правдоподобная синтетика

Хорошие тестовые данные выглядят так, будто инструментом пользуются месяц: разные даты, разные люди, типичный
беспорядок. И в них заранее зашито то, что инструмент должен найти или пережить по спеке. Каждая находка
записана в ключ ответов.

## Сначала форматы

Возьми из `SPEC.md` и `AGENTS.md`: колонки и их порядок, формат дат, разделитель дробной части, форматы
артикулов и кодов, кодировку и разделитель для csv. Один вопрос человеку: «что в настоящих файлах выглядит
не так, как я предполагаю?» Типичные ответы: лишние строки над шапкой, объединённые ячейки, два листа.

## Объём

15-20 записей для учёта и списков; 3-5 файлов для ассистента, обрабатывающего файлы; для сверок два файла
с частичным пересечением. Больше не нужно: приёмка идёт руками, человек должен успеть проверить.

## Распределение

- Даты размазаны по месяцу, с выходными, одна-две записи на границе периода.
- Суммы разного порядка: маленькие, типичные, одна крупная, один ноль.
- Имена вида «Клиент 7», «Поставщик 2», «Сотрудник 3»; никаких реальных людей, даже «случайных».
- Статусы в реальных пропорциях: большинство типичных, пара редких.

## Зашитые находки

На каждый крайний случай из таблицы спеки одна-две находки. Типичный набор:

| Крайний случай | Находка в данных |
|---|---|
| Дубль | одна запись дважды точно; ещё одна с другим написанием артикула («АБС-123/1» и «абс1231») |
| Пустое поле | строка без артикула; строка без суммы |
| Ведущие нули | артикул «00123» |
| Другой формат даты | одна дата как «2026-03-01» среди «01.03.2026» |
| Битая строка | лишний разделитель, «кракозябры» в одном поле |
| Опечатка | «Реле» и «Рел е», латинская «C» вместо кириллической «С» |
| Отсутствующая связь | ссылка на заказ, которого нет в таблице заказов |

Находок не больше 6-8 на набор, иначе данные перестают быть похожими на настоящие.

## Генерация скриптом

Скрипт `data/generate.py` (или язык проекта): фиксированное зерно случайности, чтобы данные пересобирались
одинаково; находки вставляются явно, с комментарием в коде; результат пишется в `data/test/`. Точные значения
(суммы, итоги, даты) считает скрипт, не агент «из головы».

## Ключ ответов

`data/README.md`, таблица:

| Находка | Файл | Где | Что должен сделать инструмент (по спеке) |
|---|---|---|---|
| дубль артикула | `postavshik.xlsx` | строки 4 и 11 | пометить обе ссылкой на один товар |
| пустой артикул | `postavshik.xlsx` | строка 7 | пометить «проверить», не останавливаться |

Итоговые числа для отчётов тоже в ключ: «сумма за март 19 600, средняя 4 900». На приёмке человек сверяет
результат инструмента с ключом, а не с ощущением.

## Ассистент, обрабатывающий тексты

Файлы писем или заявок: 3-5 штук, разные по длине и тону, один с недостающими данными («уточните срок» без
номера заказа), один с лишним вопросом не по теме. В ключе: что ассистент должен ответить и где должен спросить.
