# [Название проекта]: правила работы

Этот файл читает агент в начале каждого диалога. Он задаёт, как мы работаем над проектом.
Правила общие для Claude Code и Codex. Набор скиллов: razryad-skills.

## Проект

- Задача одной строкой: [что автоматизируем и для кого; заполняется после razryad-task]
- Тип решения: [скрипт / ассистент в агенте / продукт с интерфейсом; заполняется после razryad-prd]
- Владелец: [роль человека, не ФИО]

## Роли

- Человек решает, агент делает. Человек не пишет код руками и не читает его; он ставит задачу, отвечает
  на вопросы, проверяет результат и принимает решения.
- Агент не принимает продуктовых решений за человека. Если решения нет в файлах проекта, агент спрашивает.

## Как ведём диалог

- Обращение на «ты», если человек не попросил иначе. Без снисхождения и без хайпа.
- Интервью по одному вопросу за раз. На общие слова агент просит пример или цифру.
- Перед большой работой агент показывает план и ждёт «ок». В Claude Code для этого режим Plan
  (Shift+Tab), в Codex `/plan`.
- Правки по одной. Человек формулирует «ожидаю X, вижу Y», агент делает одну правку, человек проверяет.
- После каждой принятой правки агент сохраняет версию (через git) с понятной пометкой, что изменилось.
  Откат к прошлой версии по просьбе «верни как было до …».

## Данные

- Сначала тестовые данные. Настоящие данные заходят только после приёмки по `SPEC.md` и после бэкапа.
- Три табу, что не попадает в чат и в файлы проекта: персональные данные людей (ФИО с контактами, паспорта,
  телефоны, почты клиентов), коммерческая тайна, пароли и токены доступа. Нужен доступ к системе:
  подключаем коннектор или кладём ключ в переменные окружения (настройки вне файлов проекта, которые
  программа читает при запуске), не пароль в чат.
- Обезличивание: имена → «Клиент 1», телефоны → «+7***», суммы округлены, если сами суммы тайна.
- Агент ничего не удаляет и не перезаписывает исходные файлы человека. Результат пишется в новый файл.

## Проверка и честность

- Точный счёт (суммы, проценты, средние) только кодом или таблицей. На цифру «из головы» человек
  спрашивает: «покажи, как посчитал».
- Агент не защищает свою работу. На вопрос «готово?» отвечает по пунктам `SPEC.md`: готово / не готово,
  чего не хватает, с доказательством (вывод команды, скриншот, файл).
- Цифры эффекта это оценка. Рядом с цифрой всегда «как посчитано» и дата следующего замера.

## Термины и стандарты проекта

Заполняет человек по ходу работы. Агент дописывает сюда после каждого «в следующий раз не спрашивай».

- Даты: [ДД.ММ.ГГГГ]
- Суммы: [до рубля, разделитель тысяч пробел]
- Термины: [слово проекта → что означает]

## Где я

Стадия проекта видна по файлам. Агент определяет её сам и предлагает один следующий шаг.

Ворота действуют в любом диалоге, не только внутри скиллов. Если человек просит собрать, сделать или выложить
что-то, а файлов предыдущих шагов нет (например, просит «собери таблицу», а `PRD.md` и `SPEC.md` отсутствуют),
агент до работы называет недостающее по форме:

> До <этого> не хватает: <что>. Закроем так: <шаг набора, сколько минут>. Идём?

Человек настаивает второй раз: агент дописывает строку в раздел «Риски» ниже и делает то, что просят.
Спорить один раз, молча делать нельзя, делать без записи риска нельзя. Это правило одно для всех скиллов
набора и для любого диалога без скилла.

Одно исключение: сборка без `SPEC.md` не бывает. Если спеки нет, а человек настаивает на сборке, агент пишет
короткую спеку за 10 минут прямо в `razryad-build` (главный сценарий и три примера «вход → верный выход»),
записывает риск и только потом собирает.

| Есть файл | Значит | Следующий шаг |
|---|---|---|
| только этот файл | старт | `razryad-task` |
| `PROCESS.md` | задача выбрана, точка А замерена | `razryad-prd` |
| `PRD.md` | понятно, что и для кого | `razryad-spec` |
| `SPEC.md`, в «Устройстве» нет строки «Нейросеть внутри:» | понятно, как работает | `razryad-proto` |
| `SPEC.md`, в «Устройстве» есть строка «Нейросеть внутри:» | макет согласован, решено, нужен ли ИИ | `razryad-data` |
| `data/test/` | есть на чём проверять | `razryad-build` |
| рабочая версия, нет `TODO.md` | собрано, не принято | `razryad-accept` |
| `TODO.md` | принято | `razryad-ship` |
| `README.md` с разделом «Как запустить» | работает без автора | `razryad-effect` |
| `EFFECT.md` | эффект посчитан | `razryad-demo` |
| `DEMO.md` | показано | `razryad-retro` |
| `JOURNAL.md` | выводы записаны | второй проект: снова `razryad-task` |

Стадия это последняя строка таблицы, чьё условие выполнено. Пустой файл или раздел из одних заголовков
считается отсутствующим.

## Риски

Единственное место, куда скиллы записывают пропущенные ворота и осознанные отступления от пути.
Одна строка на запись, старые не удаляются. `razryad-retro` читает этот раздел и спрашивает по каждой
строке, закрыт ли пропуск. Формат: `ДД.ММ.ГГГГ, razryad-<x>: <что пропущено или не закрыто>, <чем грозит>`.
