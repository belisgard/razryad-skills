# Как определить стадию по папке

Проверь файлы в корне папки проекта в этом порядке. Первое совпадение снизу вверх даёт стадию.

| Проверка | Стадия | Следующий шаг |
|---|---|---|
| есть `JOURNAL.md` | цикл закрыт | второй проект: новая папка, `razryad-task` |
| есть `DEMO.md` | показано | `razryad-retro` |
| есть `EFFECT.md` | эффект посчитан | `razryad-demo` |
| есть `README.md` с разделом «Как запустить» и `TODO.md` | выпущено | `razryad-effect` |
| есть `TODO.md` | принято | `razryad-ship` |
| есть рабочий код или папка ассистента и `data/test/`, нет `TODO.md` | собрано, не принято | `razryad-accept` |
| есть `data/test/` или `data/README.md` | есть на чём проверять | `razryad-build` |
| в `SPEC.md` есть заголовок `## Устройство` | макет согласован | `razryad-data` |
| есть `SPEC.md` | как работает описано | `razryad-proto` |
| есть `PRD.md` | что и для кого понятно | `razryad-spec` |
| есть `PROCESS.md` | задача выбрана | `razryad-prd` |
| есть `AGENTS.md` | старт | `razryad-task` |
| папка пустая или без `AGENTS.md` | нет проекта | создать конституцию, потом `razryad-task` |

## Неоднозначные случаи

- Файл есть, но пустой или только заголовки: считай, что файла нет, и скажи об этом человеку.
- `README.md` есть, но это заглушка от генератора проекта без раздела «Как запустить»: не считается выпуском.
- «Рабочий код» для продукта: есть точка запуска (страница, скрипт, команда) и она открывается или выполняется.
  Для ассистента: есть папки входа и выхода и хотя бы один прогон записан в `SPEC.md` или журнале.
- Файлы есть, но человек говорит, что они устарели: спроси, какой из них верный, остальные не трогай.

## Как сообщать стадию

Три строки, не больше:

> Ты здесь: <стадия одной фразой>. Есть: <файлы>. Следующий шаг: `razryad-<x>`, он <что даст, одна фраза>.

Дальше один вопрос: «Идём?» или «Что-то из сделанного устарело?». Список всех скиллов набора не показывай,
если человек не спросил «а что вообще есть».
