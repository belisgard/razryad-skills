# Каркас ассистента

Ассистент это агент, который работает по правилам проекта в папке. Интерфейса нет, человек пишет фразу
запуска в чат. Каркас: папки, правила, фраза запуска и один пробный прогон.

## Папки

Предложи структуру и дождись «ок»:

```
[проект]/
  in/        входные файлы, человек кладёт сюда
  out/       результат, агент пишет сюда, исходники не трогает
  rules/     справочники и образцы (шаблон письма, список кодов, пример хорошего результата)
  data/      тестовые данные (появятся в razryad-data)
  AGENTS.md  правила проекта
```

Названия можно русские, если человеку так удобнее. Главное правило: агент читает `in/`, пишет в `out/`,
ничего не удаляет и не перезаписывает исходники.

## Правила в AGENTS.md

Допиши в раздел «Термины и стандарты проекта»:

- фраза запуска: «[обработай папку in]» или своя;
- порядок работы по шагам из `SPEC.md`;
- формат результата (имя файла, колонки, длина текста);
- проверка перед выдачей: что агент сверяет и что пишет, если данных не хватает.

Дописываем, а не переписываем. Каждое правило после «ок» человека.

## Пробный прогон

Один выдуманный входной файл, похожий на настоящий (2-5 строк). Агент выполняет задачу целиком по правилам
и по ходу ведёт список пробелов:

- где не хватило правила и пришлось догадываться;
- где спросил бы человека;
- где формат результата неочевиден.

В конце показывает результат, список пробелов и предложение, что дописать в `AGENTS.md`. Человек решает
по каждому пункту. Список пробелов главная ценность прогона: это разница между «поболтал с ИИ» и «собрал
инструмент, который работает без меня».

## «Это оно»

Человек смотрит на результат прогона и говорит, тот ли это результат по форме и содержанию. Правки по одной:
«в письме ожидаю дату из таблицы, вижу “уточните срок”». Каждая правка это новое правило в `AGENTS.md`.

## Устройство для ассистента

Чаще всего ответ: «нейросеть внутри не нужна, работает сам агент по правилам; частей решения нет, только папки».
Исключения: нужен запуск без человека и агента (расписание, коллеги без агента). Тогда это уже продукт или
скрипт, и решение об устройстве обсуждается всерьёз. Записать в `SPEC.md`, раздел «Устройство».
