# Решение об устройстве

Заполняется после «это оно». Четыре вопроса, ответы в `SPEC.md`, раздел `## Устройство`. Разговор в режиме плана:
показать план словами, дождаться вопросов и «ок», код не писать.

## 1. Нужна ли нейросеть внутри решения?

Ты, агент, в решение не встраиваешься. Если внутри нужна модель, это отдельная модель по API за отдельные деньги.
Поэтому вопрос решается консервативно.

| Задача внутри решения | Нужна ли модель | Чем делать |
|---|---|---|
| Расчёты, суммы, проценты, средние | нет | код |
| Сверка, поиск дублей, нормализация строк | нет | код |
| Конвертация форматов, сборка отчёта по шаблону | нет | код |
| Фильтры и правила «если … то …», которые можно перечислить | нет | код |
| Понять смысл свободного текста (письмо, комментарий) | да | модель по API |
| Классифицировать тексты по категориям, которые словами не перечислить | да | модель по API |
| Написать черновик текста по данным | да | модель по API |
| Извлечь поля из неструктурированного документа | чаще да, сначала попробовать правила | модель или код |

Правило: если задачу можно решить правилами, решай правилами. Модель добавляет стоимость, задержку и
ошибки «уверенным тоном». Точный счёт модели не доверяем никогда: модель может решить, что считать, но
считает код.

Если человек настаивает на модели там, где хватит кода: одна фраза о риске, строка `Риск:` в «Устройстве»,
решение за ним.

## 2. Оценка стоимости модели в месяц

Только если модель нужна. Порядок величины, не точная смета:

```
объём текста за один запуск (символов / 4 ≈ токены)
× запусков в месяц
× цена за миллион токенов (вход и выход отдельно, взять из прайса выбранной модели)
```

Пример формы записи: «~200 писем в месяц × ~2 000 токенов = 0,4 млн токенов; при цене X ₽ за млн это ~Y ₽
в месяц, оценка». Цену брать из актуального прайса, не из памяти; если интернета нет, написать «цену уточнить».

## 3. Части решения и что из них реально нужно

| Часть | Когда нужна | Когда не нужна |
|---|---|---|
| Страница (то, что видит человек) | продукт для коллег | скрипт, ассистент |
| Сервер (работает, когда ноутбук закрыт) | нужен доступ по ссылке или расписание | человек запускает сам у себя |
| Хранение (данные не пропадают между запусками) | заявки, учёт, история | разовая обработка файла в файл |
| Подключение к системам (CRM, почта, таблицы) | данные живут в системе | данные в файлах |

Начинать с минимума. Скрипт на компьютере человека это тоже решение, если по PRD пользуется он один.

## 4. На чём делаем и почему

Простыми словами, одна-две строки на выбор: «одна страница без сервера, данные хранятся в браузере, потому что
пользуется один отдел и данных немного». Готовые модули берём там, где они есть. Название технологии можно
назвать, но объяснение обязано быть на языке человека.

## Формат раздела «Устройство» в SPEC.md

```
## Устройство
- Нейросеть внутри: [нет, все шаги считаются кодом / да, для …]. Почему: […]
- Стоимость модели в месяц: [0 ₽ / ~… ₽, оценка: формула]
- Части: [страница / сервер / хранение / подключения], нужны: […], не нужны: […]
- На чём делаем: [простыми словами и почему]
- Что не решено и решится при сборке: […]
```
