# PRD: Проверка позиций поставщика на дубли в каталоге

Дата: [ДД.ММ.ГГГГ] · Владелец: категорийный менеджер · Статус: согласован

**Вердикт: скрипт.** Запускает только автор, обе таблицы лежат в файлах, правила сравнения записываются целиком,
смысл текста не нужен.

## 1. Проблема

Перед заведением новых товаров на сайт нужно проверить, нет ли их уже в каталоге. Данные поставщика и выгрузка
из учётной системы не сходятся текстуально: регистр, кириллица и латиница, пробелы, дефисы, слеши, порядок слов.
Один и тот же артикул пишут как `АБС-123/1`, `абс1231` и `АБС 123 1`. Пропущенный дубль это вторая карточка
одного товара на сайте, путаница в остатках и ручная чистка потом.

Цифра сейчас: 120 минут × 8 раз в месяц = 16 часов в месяц. Источник: оценка человека.

## 2. Пользователь

Категорийный менеджер, не программист. Работает в таблицах, командную строку использует по инструкции.
Момент: получил файл от поставщика, до заведения товаров на сайт.

## 3. Что делает

1. Читает файл поставщика и выгрузку каталога в любом табличном формате, колонки находит по настройкам.
2. Приводит артикулы и наименования обеих сторон к одному виду: регистр, пробелы, знаки, ё.
3. Ищет каждую позицию поставщика в каталоге: сначала по артикулу, если его нет, по наименованию.
4. Выдаёт таблицу в порядке поставщика: напротив каждой позиции ссылка на товар или «НЕТ».
5. Пишет отладочный файл, где видно, во что превратилась каждая строка после очистки.

## 4. Что НЕ делает

- Не сравнивает названия «по смыслу», только точное совпадение после очистки.
- Не заводит товары на сайт и не пишет в учётную систему.
- Не меняет файл каталога.
- Не имеет графического интерфейса: запуск командой.

## 5. Как поймём, что получилось

Меряем время проверки одной поставки и число дублей, созданных по позициям, которые скрипт пометил ссылкой.
Успех: меньше 5 минут на поставку, ноль таких дублей за месяц.

## 6. Приёмочные критерии

- [ ] Запуск на тестовой паре файлов проходит без ошибок и создаёт файл результата.
- [ ] `АБС-123/1` у поставщика и `абс1231` в каталоге дают ссылку.
- [ ] Пустой артикул и наименование `Смартфон (Xiaomi) Redmi` находят товар по наименованию.
- [ ] Позиция `NEW001`, которой нет в каталоге, даёт «НЕТ».
- [ ] Артикул `00123` остаётся `00123` в результате, таблица показывает его текстом, не числом.
- [ ] Число строк и порядок в результате совпадают с файлом поставщика.
- [ ] Запуск с неверным именем колонки печатает список настоящих колонок файла.
- [ ] Запуск при открытом файле результата даёт понятное сообщение, не ошибку программы.
- [ ] Файл каталога после прогона не изменён.
- [ ] Прогон на настоящей паре файлов после приёмки: ручная сверка пяти известных дублей сходится.

## Ответы развилки

- Кто кроме автора запускает: никто.
- Данные: выгрузки в файлах на компьютере.
- Работать при выключенном компьютере: нет.

## Что делает этот пример хорошим

- Каждая функция глагол с результатом, ни одного «удобно» и «быстро».
- Границы отсекают соблазны: «по смыслу», «сразу заводить на сайт», «интерфейс».
- Критерии с конкретными значениями: по ним ответ «готово» или «нет» без спора.
- Цифра боли с формулой и источником, а не «долго».
