# razryad-accept: готово ли?

Приёмка по `SPEC.md`, а не по «нравится». По каждому пункту вердикт «готово / не готово, чего не хватает»
с доказательством. Каждый пример «вход → верный выход» прогоняется, фактический выход показывается рядом
с ожидаемым. Всё, что не готово, ложится в `TODO.md` по трём корзинам. Нормально, если готово не всё:
главное действие работает, значит инструмент есть, остальное живёт в списке, а не в панике.

## Что это / что не это

Это: проверка каждого пункта спеки с доказательством: вывод команды, скриншот, файл результата.
Это: прогон примеров «вход → верный выход» и находок из ключа ответов `data/README.md`.
Это: честный `TODO.md`: сейчас, потом, никогда. Корзину выбирает человек.
Не это: правки. Нашёл дыру, запиши в `TODO.md`, чинить через `razryad-build` после приёмки.
Не это: «в целом всё хорошо». Такого вердикта не бывает, есть список пунктов и по каждому да или нет.
Не это: правка `SPEC.md` под то, что получилось. Спека меняется только по решению человека.

## Как ведём себя

- Агент не защищает свою работу. Расхождение это «не готово», а не «особенность данных».
- Вердикт без доказательства не вердикт. Показывай, а не рассказывай.
- Человек сам проходит хотя бы главный сценарий. Слово агента «проверил» этого не заменяет.
- По одному вопросу за раз, когда нужно решение человека: корзина, спорный пункт.
- Точный счёт только кодом: если пример требует сумму, покажи, как посчитано.
- Ничего не чини по ходу: приёмка идёт до конца, потом правки.

## Шаг 0. Контекст

Прочитай `AGENTS.md`, `SPEC.md` целиком, `data/README.md` (ключ ответов, если есть). Убедись, что рабочая
версия существует: для продукта есть точка запуска и она открывается, для ассистента есть папки входа и выхода
и хотя бы один прогон. Если рабочей версии нет, назови `razryad-build` и не начинай. Если нет `SPEC.md`,
назови `razryad-spec`.

Обзор с вертолёта (5-8 строк до первого действия): что будет к концу (таблица вердиктов по спеке
и `TODO.md`), три шага, 20-40 минут, где решает человек (сам проходит главный сценарий, выбирает корзины,
решает, выпускать ли), где делает агент (прогоняет примеры, собирает доказательства). Нормально,
если готово не всё.

## Шаги

1. Составь список пунктов проверки из `SPEC.md`: шаги главного сценария, крайние случаи, примеры
   «вход → верный выход», состояния экрана (если есть интерфейс), доступы (кто не должен мочь).
   Покажи список, жди «ок». → `references/rubric.md`
2. Попроси человека пройти главный сценарий самому, 2-4 действия. Его наблюдение записывается первым.
3. Прогони каждый пример «вход → верный выход»: покажи ожидаемый и фактический выход рядом. Совпало
   до значения: готово. Иначе: не готово, чего не хватает.
4. Сверь находки из `data/README.md`: что инструмент должен был найти, что нашёл, что пропустил, что нашёл лишнего.
5. По остальным пунктам вердикт с доказательством: команда и её вывод, скриншот, путь к файлу результата.
   Расхождение со спекой это «не готово», даже если результат кажется разумным.
6. Всё «не готово» покажи списком. По каждому пункту один вопрос человеку: сейчас, потом или никогда?
   Про «сейчас» переспроси: точно ли без этого нельзя выпускать. → `assets/TODO.template.md`
7. Запиши `TODO.md`, сохрани версию с пометкой «приёмка по спеке».

## Формат результата

Файл `TODO.md` по шаблону `assets/TODO.template.md`. Обязательно: дата приёмки; таблица вердиктов по всем пунктам
`SPEC.md` с колонками «пункт / вердикт / доказательство»; примеры «вход → выход» с ожидаемым и фактическим
значением; три корзины: сейчас (до выпуска), потом (после выпуска), никогда (сознательно не делаем и почему).
Пустая корзина остаётся с заголовком и строкой «пусто».

Каждый вердикт в разговоре звучит так:

> <пункт>: не готово. Ожидал <Y>, получил <Z>. Не хватает: <что>. Доказательство: <вывод или файл>.

## Ворота

Дальше нельзя, пока не выполнено: все примеры «вход → верный выход» из `SPEC.md` прогнаны и фактический выход
показан; у каждого вердикта есть доказательство; человек сам прошёл главный сценарий; корзина «сейчас» пуста
или человек явно решил выпускать с ней. Если «сейчас» не пуста, а человек говорит «выпускаем»:

> До выпуска не хватает: <пункты из «сейчас»>. Без них <чем грозит, одна фраза>. Закроем так: <оценка, один
> заход в razryad-build>. Или выпускаем с этим осознанно?

Настаивает: в конец `TODO.md` строка `Риск: выпуск с открытыми пунктами <список>, <чем грозит>`,
и передай в `razryad-ship`. Спорить один раз.

## Дальше

`razryad-ship`, если корзина «сейчас» пуста или риск записан. `razryad-build` в режиме правок, если в «сейчас»
есть пункты и человек решил их закрыть: после правок вернись сюда и перепроверь только эти пункты.
`razryad-spec`, если приёмка показала, что спека описывает не то: правка спеки решением человека, потом снова сюда.
