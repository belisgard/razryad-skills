# Чек безопасности перед выпуском

Три вопроса до того, как инструмент увидят другие: что утекло в файлы, кто получит доступ, что будет
с настоящими данными. Проверяет агент, решает человек.

## 1. Секреты и настоящие данные в файлах

Агент ищет сам, по файлам проекта и по сохранённым версиям:

- пароли, токены, ключи доступа: строки вида `password=`, `token`, `api_key`, `secret`, длинные случайные
  последовательности, файлы `.env` и конфиги с учётными данными;
- настоящие персональные данные: ФИО с телефонами и почтами, паспортные данные, адреса клиентов;
- коммерческие данные, которых не должно быть в тестовом наборе: реальные суммы контрактов, цены, финансовые выгрузки.

Нашёл: покажи человеку список файлов и строк (сами значения не повторяй в чате целиком), предложи:

1. вынести секреты в переменные окружения (настройки вне файлов проекта, которые программа читает при
   запуске) или в настройки коннектора, из файлов убрать;
2. заменить настоящие данные тестовыми из `data/test/`;
3. убрать следы из сохранённых версий, если секрет уже попал в историю, и сменить сам секрет: то, что было
   в истории, считается раскрытым.

До выкладки этот пункт закрыт. Исключений нет.

## 2. Кто имеет доступ

- Ссылка без пароля означает: любой, кто её узнает. Для инструмента с рабочими данными минимум пароль на вход.
- Спроси: кто должен видеть результат, кто не должен (чужие отделы, подрядчики, внешние люди).
- Для расписания: кто получает уведомления и кто может остановить процесс.
- Запиши в `README.md` раздел «Данные»: что инструмент читает, что уходит в модель, что нет.

## 3. Первые настоящие данные

До этого момента инструмент работал на `data/test/`. Переключение на рабочие данные по порядку:

1. **Бэкап исходников.** Копия рабочих файлов или выгрузка из системы в отдельную папку с датой. Агент делает копию,
   человек подтверждает, что она открывается.
2. **Прогон на копии.** Инструмент работает с копией, не с оригиналом. Результат проверяет человек по примерам
   из `SPEC.md`.
3. **План отката.** Одна строка в `README.md`: что сделать, если результат неверный (взять бэкап от такой-то даты,
   остановить расписание).
4. **Переключение.** Только после успешного прогона на копии. Первый рабочий запуск под присмотром человека.

Правило из `AGENTS.md` действует и здесь: агент не удаляет и не перезаписывает исходники человека.

## 4. Куда писать об ошибках

В `README.md` раздел «Если не работает»: скопировать текст ошибки целиком, отправить владельцу (роль, канал).
Для расписания: где журнал запусков и как перезапустить руками.
