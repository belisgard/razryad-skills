# Работа по расписанию

Рутина, которая запускается сама: каждый день в 9:00, каждый понедельник, при новом письме или заявке.
Человек только смотрит результат и получает сообщение, если что-то сломалось.

## Три части любого автоматического процесса

| Часть | Что это | Примеры |
|---|---|---|
| Триггер | что запускает | время по расписанию; новое письмо; новый файл в папке; сообщение боту; заявка с сайта |
| Обработка | что делает инструмент | сверка, расчёт, сводка, запрос к модели, запись в таблицу |
| Выход | куда отдать результат | письмо; сообщение в чат; файл в папке; строка в таблице |

Без выхода процесс бесполезен: результат должен появиться там, где человек его увидит без напоминания.

## Где это запускать

Выбор зависит от того, что уже есть. Агент предлагает один вариант с обоснованием, человек решает.

- **Планировщик на сервере.** Если продукт уже на сервере: команда запускается по расписанию встроенным
  планировщиком. Самый простой и надёжный вариант для «раз в день».
- **Конструктор автоматизаций.** Визуальные блоки «триггер → обработка → выход», сотни готовых подключений к почте,
  чатам, таблицам. Подходит для процессов по событию и когда нужно связать несколько сервисов. Ставится на свой сервер.
- **Агент по расписанию.** Для ассистента в агенте: задача агенту запускается по времени и делает рутину
  по правилам из `AGENTS.md`. Подходит для сводок и отчётов из файлов.

## Обязательные условия

1. **Уведомление об ошибке.** Если запуск упал, человек получает сообщение с текстом ошибки. Молчаливая поломка
   хуже отсутствия автоматизации: результат перестаёт приходить, и это замечают через месяц.
2. **Первый запуск под присмотром.** Триггер срабатывает при человеке, он смотрит результат и подтверждает.
   Потом ещё два запуска проверяются на следующий день.
3. **Журнал запусков.** Дата, время, успех или ошибка, сколько обработано. Файл или строка в таблице.
4. **Тестовые данные до настоящих.** Первые запуски на `data/test/`, потом переключение на рабочий источник
   с бэкапом (см. `security.md`).

## Что записать

В `README.md`: когда запускается, куда приходит результат, где журнал, что делать, если результат не пришёл
(проверить журнал, перезапустить руками, написать владельцу). В `AGENTS.md`: где живёт настройка расписания.
