# Свой скилл или агент для коллеги

Ассистент в агенте живёт как папка с правилами. Чтобы им пользовался коллега, рутину упаковывают в скилл:
файл с инструкцией, который агент сам находит и применяет, когда задача похожа. Писать его руками не надо,
агент собирает файл по ответам человека.

## Что внутри скилла

Три части, всё обычным текстом:

1. **Когда включать.** Фразы, которыми человек просит эту работу: «собери недельную сводку», «проверь счёт».
2. **Шаги.** Откуда взять вход, что сделать, как проверить результат перед выдачей.
3. **Шаблон и правила.** Формат результата, стандарты проекта (даты, суммы, термины) из `AGENTS.md`.

## Как собрать

Задай 3-5 вопросов по одному, потом создай файл сам:

1. Какой фразой коллега попросит эту работу? (Нужны 3-4 варианта, как он реально скажет.)
2. Что лежит на входе и где? Что должно получиться на выходе и в каком виде?
3. Как понять, что результат правильный, до того как отдать? (Проверка из `SPEC.md`, примеры «вход → выход».)
4. Что коллега точно не должен получить (границы из `PRD.md`)?
5. Какие термины и стандарты нужно знать? (Перенести из `AGENTS.md`.)

Собери файл скилла, положи его в папку проекта и проверь на тестовом файле из `data/test/`: попроси выполнить
работу одной из фраз-триггеров и сравни результат с ожидаемым.

## Где живёт

- **В папке проекта.** Едет вместе с проектом, общий для всех, кто открывает эту папку. Выбор по умолчанию
  для инструмента команды.
- **В личной папке пользователя агента.** Работает у одного человека во всех его проектах. Для личной рутины.

Агент подскажет пути для Claude Code и Codex, человек выбирает уровень. Если коллега работает в другом агенте,
файл скилла всё равно текст: перенести можно копированием.

## Агент как узкий специалист

Если рутина делится на роли (один собирает цифры, другой причёсывает текст), к скиллу добавляется агент:
отдельная роль с чистым контекстом и одной задачей. Правило: одна задача на агента, узкая роль, чёткое описание.
Собирается тем же способом: 3-5 вопросов, файл создаёт агент.

## Коннекторы к системам

Если для рутины нужны данные из рабочей системы (таблицы, чат, задачник, база):

1. Есть готовый коннектор к этой системе (MCP), берём его. Агент подключает и проверяет, человек подтверждает доступ.
2. Нет готового, у системы почти наверняка есть программный доступ (API). Агент напишет переходник сам.
3. Ключи доступа только через переменные окружения или настройки коннектора. Никогда в текст скилла и в чат.

## Что записать

В `README.md` для коллеги: какой фразой запустить, что положить на вход, где результат, что проверить глазами.
Файл скилла проверен на тестовом файле, результат совпал с примером из `SPEC.md`.
